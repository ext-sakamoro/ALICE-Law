# Changelog

All notable changes to this repository are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
This repository is not published as a crate (its package is `0.0.0`); its scripts and
workflows are the interface, so changes to what they check are recorded here.

## [Unreleased]

### Added
- `scripts/public_text_check.py`: in a commit message, the ids the current work sessions go by (held as SHA-256) are findings as whole tokens, without the review-word context file text needs (a parenthesised id at the end of a subject was missed); an id of digits only only in brackets or after "by" / "from" / "cc" / "per", not a number's exponent, not inside a code span; file text keeps the context rule
- `scripts/public_text_check.py`: zlib streams, gzip members and zstd frames at any offset of a binary file (a compressed debug section of a compiled library, for example) are inflated and read for build paths, within the same size budget; a stream that breaks off is read up to where it breaks; a stream over the budget is an `unscanned container` finding; build paths are counted as distinct whole paths (`\` read as `/`), so a path stored twice, or both as it is and compressed, is one
- `.github/workflows/e2e.yml`: the published releases run on aarch64 and on x86_64, and a job requires the two digests to be equal and equal to the golden (as in main mode)
- `scripts/public_text_check.py` `ALLOWED`: an entry for ALICE-LOL (a directory of the product's own distribution named in one test file, 2 lines)
- `e2e/`: equal zeros meeting a min or a max on public paths of alice-physics and alice-sdf (stored, restored, compared and in the digest); alice-edge's fixed-point fit and its `SignalLaw` stored and restored through the alice-db law store; alice-edge's `SEMANTICS_ID` among the identifiers, and the identifier pinned to its hex; alice-edge among the core crates (`scripts/main_mode.py`, the e2e-main repositories)
- `.github/workflows/e2e-main.yml`: the run on aarch64 and on x86_64, and a job that requires the two digests to be equal and equal to the golden
- `scripts/public_text_check.py`: a home directory compiled into a tracked binary file is a finding given as the path and the number of paths, never the text: the bytes are read as they are and as UTF-16 (both byte orders and alignments); a path has either separator, may be glued to the text before it and may have any user name (`/Users/<name>/`, `/home/<name>/` but a placeholder's or the CI runner's, cargo's registry or git checkout under any home but the runner's or under `/root`), and does not count inside a URL; zip / jar / apk / tar / gzip / bzip2 / xz / zstd / zlib members are read (nested, up to a depth and a size), and a container that cannot be read is an `unscanned container` finding, a Git LFS pointer an `unscanned LFS object` finding; these classes and `binary home path` may be allowed for a single file at a pinned count; a regular file git takes as binary that was not read as binary is a finding; a symbolic link is read as its target's name and a submodule entry is skipped and reported (it no longer stops the check); zstd is read with the standard library of Python 3.14 (the workflow sets it up; an older Python reports a zstd stream as an unscanned container and says so); `release_train.py publish-gate` applies the same check to the files of the package
- `release_train.py publish-gate`: Actions variables and Dependabot secrets are inventoried and must be declared (`[variables]`, `[secrets]` `dependabot:<name>`); every list is paginated and counted; a self-hosted job on a release / tag / dispatch / schedule trigger needs an environment with required reviewers or a `[self-hosted]` declaration
- `release_train.py publish-gate`: the repository's Actions secrets are read from GitHub and must be declared in `release-train.toml` `[secrets."<repository>"]` (`purpose`, `publishing`); a publishing credential outside an environment with required reviewers is refused, and so is a job that receives a publishing secret, an inherited secret or an OIDC token on a release / tag / dispatch / schedule trigger outside such an environment
- `scripts/public_text_check.py`: device names in any case; a device detail class (an SDK or board support package name with its version, a release string on or next to a device line); a host name class held as SHA-256 (the list is supplied privately)
- `release_train.py publish-gate`: refuses a repository whose workflows can publish outside the gate: by job, a crates.io credential or publish command anywhere; a PyPI / npm credential or publish command in a job whose environment has no required reviewers
- `scripts/public_text_check.py`: a user's home directory path (`/Users/<name>/`, `/home/<name>/`) is a finding; `release_train.py publish-gate` also refuses a package carrying `logs/`; `release-train.toml`: alice-llm 2.0.0 (incompatible with 1.6.0)
- `release_train.py publish-gate`: every file of the package is read by `scripts/public_text_check.py` (the source repository's settings and allow-list); internal text in the package is refused
- `scripts/public_text_check.py`: the session name, session id, device and private address classes are allowed only for a single file
- `scripts/public_text_check.py`: an `allow` array of tables under `[public-text]` in a repository's `.public-text.toml` (`path`, `class`, `count`, `why`: a kind of finding allowed in a file or directory at a pinned number of lines; never a private name or path) and `--suggest-allow <ref> <scope>`, which prints those entries with the counts found
- `release_train.py publish-gate`: every crate needs a `## [<version>] - YYYY-MM-DD` release heading in its CHANGELOG (an undated or placeholder heading, a date that does not exist or one after tomorrow is refused), and the checkout must still be clean after `cargo package`
- `scripts/dep_consistency.py`: one version of every `alice-*` crate in `Cargo.lock`, all eight core crates present, and every `alice-*` requirement (this repository's and those of the resolved releases) accepting the latest release
- `scripts/dep_consistency.py --roster`: problems a coming release removes are listed in `release-train.toml` under `[pending.<name>]` (`until`, `linked`, `requires`) and reported as expected with a count; an unlisted problem, an entry whose release is published, and a listed item that matches nothing fail the check
- `release-train.toml` and `scripts/release_train.py`: the release plan of the core crates (version, order, state) and `next`
- `release_train.py publish-gate`: refuses a publish from a checkout that is not the commit, a crate that is not `prepared`, a manifest that overrides an `alice-*` crate or takes one from another registry, a version already on crates.io, and an `alice-*` requirement on a crate that is not published or not accepted; also `must-contain` commits, `must-contain-patch` patch ids (`git patch-id --stable`), `changelog-has` lines in the `## [<version>]` section, `required-ci` jobs (exactly the expected legs of the named workflow's latest run, all completed with success; an entry with `since` applies from that version on), and a package that carries `.github/`, `scripts/`, `docs/` or private notes; on go it builds the package with `cargo package` and prints its sha256 and the `cargo publish` command
- `release_train.py publish-verify` and `roster-mark published`: after a publish, crates.io's version, yank state, checksum (against the gate's sha256), license and owners, the downloaded `.crate`'s commit (`.cargo_vcs_info.json`) and the remote tag are compared with the published commit; the roster state changes to `published` only when that passes
- `release_train.py followups`: every `Cargo.toml` of the roster's repositories with a requirement on a crate that does not accept its roster version
- `scripts/expected_failure.py`: a CI step that fails until a release is listed under `[expected-failure.<name>]` (`step`, `until`, `expect`, `why`); only a failure whose own error lines (any case, colour codes removed) are all explained by the expected text, and whose exit status is the entry's `exit` when it names one, passes, and the steps that need it are skipped; every run lists the entries in the job summary and `--check` fails on an entry no workflow runs; the end to end workflows use it until alice-lol 0.4.0
- `scripts/public_text_check.py`: file contents, paths and commit messages checked for internal vocabulary (private names held as SHA-256 hashes, parts split at `-` `_` `.` too); run by `scripts/preflight.sh` before a push and by `.github/workflows/public-text.yml` on every push
- `e2e/`: read a law, compute, save, restore and compare every value bit for bit, against the published releases and against the main branches (`scripts/main_mode.py`), with mutations the test must catch (`scripts/e2e_teeth.py`)
- `docs/CONFORMANCE.md` and `conformance/gates.toml`: the 14 gates a Law-bearing crate's arithmetic must meet (G1 banning a direct platform transcendental call through G14 banning a build flag that changes floating-point semantics), in human-readable and generator-readable form; each gate's definition, the kinds of evidence a passing crate must cite, and the manifest shape (`status`/`evidence`/`since`/`note`/`reference_repo`) a crate's own `alice-law-conformance.toml` follows
- `scripts/readme_roster_check.py`: fails when README.md's intro paragraph (whole-name matched, not substring) falls behind `release-train.toml`'s roster
- `scripts/conformance_docs_schema_check.py`: fails when a `### G<n> — <name>` heading in `docs/CONFORMANCE.md` and the matching `[[gate]]` entry in `conformance/gates.toml` disagree in id, name, or count
- `release_train.py publish-gate`: the packaged `.crate` is unpacked into a directory with no `Cargo.lock` or `Cargo.toml` above it and built as the dependency of an empty crate (as a crates.io consumer builds it); a failed build or one that compiled no library of the crate is refused
- `release_train.py publish-gate`: the consumer build runs with an empty `CARGO_HOME` and a minimal environment, refuses a `.cargo/config` above the build directory, and builds the default features, no default features and every feature (or the roster's `consumer-features` sets, with `consumer-features-why`); a crate with no library is built on its own from outside its directory, and a `.crate` carrying a Cargo configuration (`.cargo/config`, `.cargo/config.toml`) is refused
- `release-train.toml` `consumer-check-features` (compiled with `cargo check`, not linked: Python extensions, linked by maturin) and `consumer-expected-failure` (`features`, `expect = {code, file, text, count, message?}`, `until`, `why`, optional `command`: a set whose every error of the crate itself, read from cargo's JSON diagnostics, is that error until that release; passing, any other error or reaching the release is refused); alice-zip-cli, alice-db, alice-physics, alice-sdf and alice-edge declare their sets, and alice-db 0.4.0's `python` (two versions of ndarray on a fresh resolve) is an expected failure until alice-db 0.4.1
- `scripts/public_text_check.py`: an id-like token (two hex digits, not glued to a digit, letter, `#`, `_`, `-` or `.`) next to a word naming a review or a session, on either side, and the labels of review findings, in file contents and commit messages; no list of ids is held (two-digit ids are enumerable even hashed)
- `scripts/public_text_check.py --allow-hash <path> <name>` and `ALLOWED`: a product's mention of a private name allowed per repository (from the origin URL, or `--repo-name`) and file, held as `sha256(path NUL name)`; an entry that allows nothing in `--tree` fails; commit messages are never allowed
- `scripts/public_text_check.py`: the word for a work period used as a unit of the work (after or before Japanese text, its multi- form, with a letter, the next-one phrase over two comment lines); any `[[name]]` link with an underscore or hyphen outside a TOML array-of-tables header; private note names in prose and note frontmatter keys; home-directory paths into private repositories (names held as SHA-256 in `scripts/public_text_private_repos.txt`); the agent word that names the Cloudflare runtime crate is not a finding only in that crate's places and in `.public-text.toml` `technical-paths`; `.public-text.toml` `upstream-fork` with `upstream-base` (a fork reads every commit and changed file after its fork point) and a finding for every change of that file; binary files read as printable runs of six or more characters, ASCII and UTF-16; allow-list entries scoped to a file or a directory prefix with a pinned line count, for private names, agent words and links; the entries of ALICE-SDF, text-to-print and voicebox; `--range` reports the files it read
- `release-train.toml` `consumer-expected-failure` `expect.label`: the primary span's label, so a new error on the same text elsewhere is refused (alice-db's entry pins it)
